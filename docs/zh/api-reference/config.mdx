### 更新系统配置

更新系统配置的各个部分。您只需提供要更新部分的键。

- **端点**: `/api/system-config`
- **方法**: `PUT`
- **正文**: 一个 JSON 对象，包含以下一个或多个顶级键：`routing`、`install`、`smartRouting`、`toolResultCompression`、`mcpRouter`、`dashboardName`、`dashboardBranding`。

#### 控制台品牌 (`dashboardName`、`dashboardBranding`)

仅管理员可用。

- `dashboardName` (string): 显示在侧栏、登录页和浏览器标签中的名称，去除首尾空格后最多 100 个字符。空字符串恢复默认名称。
- `dashboardBranding` (object): 可选图片。只需发送要修改的槽位；省略的槽位保持不变，空字符串清空该槽位。
  - `icon` (string): 方形标志，用于折叠侧栏、浏览器标签页图标和 OAuth 授权页。
  - `logoLight` (string): 浅色主题的宽幅 Logo（展开的侧栏、登录页）。
  - `logoDark` (string): 深色主题的宽幅 Logo；未设置时使用 `logoLight`。

每张图片必须是 base64 `data:` URL，类型为 `image/png`、`image/jpeg`、`image/webp` 或 `image/svg+xml`，解码后不超过 256 KB，且内容与声明的类型一致。`PUT /api/system-config` 和 `GET /api/settings` 以相同的带版本 URL 返回各槽位，而不是图片数据；设置导出仍保留图片数据以便恢复。其他情况（远程 URL、其他类型、无效 base64、超出大小、未知槽位）会返回 HTTP 400，并在消息中指出槽位，例如 `dashboardBranding.icon must be at most 256 KB`。

```json
{ "dashboardBranding": { "icon": "data:image/png;base64,iVBORw0KGgo...", "logoDark": "" } }
```

#### 路由配置 (`routing`)

- `enableGlobalRoute` (boolean): 启用或禁用全局 `/api/mcp` 路由。
- `enableGroupNameRoute` (boolean): 启用或禁用基于群组的路由 (例如 `/api/mcp/group/:groupName`)。
- `enableBearerAuth` (boolean): 为 MCP 端点启用 Bearer 令牌身份验证（默认：`true`）。
- `bearerAuthKey` (string): 旧版 Bearer 密钥（仅用于一次性迁移）。
- `skipAuth` (boolean): 如果为 true，则跳过仪表盘 / Web API 的登录要求，前端可在没有会话令牌的情况下访问 `/api` 路由。未登录的仪表盘用户会被视为内置 `guest` 管理员，因此仅应在受信任环境中启用，但**不会**关闭 MCP 端点认证。

#### 安装配置 (`install`)

- `pythonIndexUrl` (string): 用于安装的 Python 包索引 (PyPI) 的基础 URL。
- `npmRegistry` (string): 用于安装的 npm 注册表 URL。
- `baseUrl` (string): 此 MCPHub 实例的公共基础 URL，用于 MCP 请求与 OAuth 回调地址。

#### 智能路由配置 (`smartRouting`)

- `enabled` (boolean): 启用或禁用智能路由功能。
- `dbUrl` (string): 用于存储嵌入的数据库连接 URL。
- `llmProviderBaseUrl` (string): 用于生成嵌入的 OpenAI 兼容 API 的基础 URL。
- `llmProviderApiKey` (string): 嵌入服务的 API 密钥。
- `embeddingModel` (string): 要使用的嵌入模型的名称。
- `embeddingDimensions` (number，可选)：对于支持自定义维度的提供方，指定嵌入输出维度；不设置时使用模型默认值。该值同时声明了预期的存储维度，但仅对已知支持 Matryoshka（MRL）表示的模型、或开启 `embeddingDimensionsApiPassthrough` 时，才会作为 `dimensions` 请求参数转发给提供方（issue #1131）。
- `embeddingDimensionsApiPassthrough` (boolean，可选，默认 `false`)：设为 `true` 时，始终将 `embeddingDimensions` 作为 `dimensions` 请求参数转发给提供方。非 MRL 模型/后端（Qwen3-Embedding、BGE、vLLM/sglang 等）会直接拒绝该参数；仅对其它支持 MRL 的模型开启。参见 `EMBEDDING_DIMENSIONS_API_PASSTHROUGH`。

#### 工具结果压缩配置 (`toolResultCompression`)

- `enabled` (boolean): 是否对成功的工具结果启用透明压缩。
- `minTokens` (number): 单个文本块达到或超过该估算 token 数时才会压缩。默认值：`2000`。
- `maxOutputTokens` (number): 每个压缩后文本块的目标 token 预算。默认值：`1200`。
- `strategy` (string): 压缩策略。允许值：`auto`、`json`、`log`、`search`、`diff`、`text`。默认值：`auto`。

压缩只作用于成功的工具响应。`isError: true` 的响应和非文本内容块会原样返回。活动日志会在压缩前记录上游原始输出。

#### MCP 路由器配置 (`mcpRouter`)

- `apiKey` (string): MCP 路由器服务的 API 密钥。
- `referer` (string): 用于 MCP 路由器请求的 referer 头。
- `title` (string): 在 MCP 路由器上显示的此实例的标题。
- `baseUrl` (string): MCP 路由器 API 的基础 URL。

#### OAuth 服务器外部资源 (`oauthServer.externalResources`)

仅管理员。让 MCPHub 的授权服务器为 MCPHub 之外的受保护服务签发 JWT 访问令牌 (RFC 9068)，这些服务可用 `/.well-known/oauth-authorization-server` 中的 `jwks_uri` 自行验证令牌。传入 `null` 或 `[]` 清空列表。

- `resource` (string): 绝对 https URL（仅 `localhost`、`127.0.0.1`、`[::1]` 允许 http），不含片段或凭据。客户端的 RFC 8707 `resource` 参数必须与之完全一致。
- `name` (string): 在授权页和已连接客户端中显示的名称。
- `allowedClients` (string[]，可选): 可请求该资源的 OAuth 客户端 ID；为空或省略表示任何已注册客户端；以 URL 作为 ID 的客户端（CIMD）不在此默认范围内，必须按其 URL 显式列出。
- `scopes` (string[]，可选): 为该资源授予的 scope（并写入 JWT 的 `scope` 声明）；请求中未列出的 scope 会被丢弃，省略表示不授予任何 scope。这里列出的 scope 在客户端注册（`POST /oauth/register`）时也会被接受，无需在 `oauthServer.allowedScopes` 中重复列出；它们不会加入 MCPHub 自身元数据的 `scopes_supported`。

- `skipConsentForPersonalConnection` (boolean，可选，默认 `false`): 为 `true` 时，MCPHub 自带的个人连接客户端（`mcphub-personal-oauth`，当个人 OAuth 服务器的 `url` 等于该资源时使用，见 ADR 0015）为该资源获取授权码时不显示授权页：管理员的配置即同意，用户开启该服务的操作即触发。它只对该客户端生效，且仅限其自身回调地址，并要求请求的每个 scope 都列在 `scopes` 中（请把服务公布的所有 scope 都列上，否则仍会显示授权页）。其他客户端（以 URL 作为 ID 的 CIMD 客户端和已注册客户端）仍会看到授权页。每次跳过都会写入日志 `OAuth consent skipped for the administrator-trusted resource`，包含用户、客户端、资源和 scope。若希望用户逐次确认连接，请保持关闭。

令牌包含 `sub`（MCPHub 用户名）和 `mcphub_uid`：后者是标识账号的 UUID，在账号整个生命周期内不变，且绝不会分配给其他账号，即使已删除用户的用户名被他人重新使用。资源服务应以（`iss`，`mcphub_uid`）作为每个用户数据的键，把 `sub` 仅当作显示名；为保持兼容，`sub` 不变。数据库模式下它就是用户的主键（无需修改表结构）；文件模式下它保存在 `mcp_settings.json` 中用户的 `stableId` 字段，创建用户时生成，旧用户首次签发令牌时自动补上。详见 ADR 0014。

既不是 MCPHub 自身来源、也不在列表中（或客户端无权使用）的 `resource` 会以 `invalid_target` 拒绝。签发的令牌不能用于 MCPHub 自身的路由。由于服务端离线验证，外部令牌有效期为 `min(accessTokenLifetime, oauthServer.externalTokenLifetimeSeconds)`（默认 900），并要求已配置公共基础 URL。轮换后的签名密钥立即发布，并在 `oauthServer.signingKeyActivationDelaySeconds`（默认 900）之后才开始签名。`POST /api/oauth/signing-keys/rotate`（仅管理员）会改用新密钥签名，旧公钥在其令牌过期前继续发布。详见 ADR 0014。

- **请求示例**:
  ```json
  {
    "routing": {
      "enableBearerAuth": true,
      "skipAuth": false
    },
    "smartRouting": {
      "enabled": true,
      "dbUrl": "postgresql://user:pass@host:port/db"
    },
    "toolResultCompression": {
      "enabled": true,
      "minTokens": 2000,
      "maxOutputTokens": 1200,
      "strategy": "auto"
    }
  }
  ```

### 获取所有设置

检索实例的整个设置对象，包括所有服务器配置、群组和系统设置。这是 `mcp_settings.json` 文件的完整转储。

- **端点**: `/api/settings`
- **方法**: `GET`

### 获取运行时配置

检索前端应用程序所需的基本运行时配置。此端点不需要身份验证。

- **端点**: `/config`
- **方法**: `GET`
- **成功响应**:
  ```json
  {
    "success": true,
    "data": {
      "basePath": "",
      "name": "MCPHub"
    }
  }
  ```

### 获取版本号

返回正在运行的 MCPHub 版本。未登录的调用方拿不到版本号：`/config`、`/public-config`、健康检查端点、MCP `initialize` 响应和控制台静态文件都不包含版本号，响应也不带 `X-Powered-By` 头。此端点仅限管理员，其他已登录用户会收到 `403`。更新检查（`/api/changelog/update-info`）同样仅限管理员。

- **端点**: `/api/version`
- **方法**: `GET`
- **成功响应**:
  ```json
  { "success": true, "data": { "version": "1.0.0" } }
  ```

### 获取公共配置

检索公共配置，主要用于检查是否跳过身份验证。这允许前端在用户登录前相应地调整其行为。此端点不需要身份验证。

- **端点**: `/public-config`
- **方法**: `GET`
- **成功响应**:
  ```json
  {
    "success": true,
    "data": {
      "dashboardName": "",
      "dashboardBranding": { "icon": "/api/branding/icon?v=3f9a1c0d2b7e", "logoLight": "", "logoDark": "" },
      "skipAuth": false,
      "permissions": {}
    }
  }
  ```

`betterAuth` 包含登录页需要的、实际生效的 Better Auth 设置：已启用的提供商、`disablePasswordLogin`、`loginMode`（`dual`、`sso_first` 或 `sso_redirect`，已按当前能登录的提供商计算好）以及 `providers.oidc.displayName`。参见 [登录页展示方式](/zh/features/authentication)。

`dashboardName` 和 `dashboardBranding` 让登录页在登录前即可显示已配置的品牌。未设置的图片为空字符串，已设置的为同源 URL（带 `BASE_PATH` 前缀），其 `v` 查询参数由图片内容生成。

#### 获取品牌图片

- **端点**: `/api/branding/{slot}`，`slot` 为 `icon`、`logoLight` 或 `logoDark`
- **方法**: `GET`（无需身份验证）
- **响应**: 原始图片及其 `Content-Type`、`X-Content-Type-Options: nosniff`、强 `ETag`（字节的 SHA-256）、仅当 `v` 查询参数与所返回的内容一致时才使用 `Cache-Control: public, max-age=31536000, immutable`（不带 `v` 时为 `no-cache`，版本不是当前版本时为 `no-store`）；SVG 还带有 `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; sandbox`。`If-None-Match` 匹配时返回 `304`，槽位未知或未设置时返回 JSON `404`。
